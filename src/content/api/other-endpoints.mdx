Smaller endpoints that don't belong to one resource.

## `GET /api/health`

<Badge text="GET" variant="info" size="medium" /> <Badge text="No session required" variant="default" size="medium" />

Checks connectivity to the configured storage backend — the same probe
used in the [Docker](/deployment/docker#health-checks) and
[Kubernetes](/deployment/kubernetes) health checks.

**Response:** `200 { "status": "ok" }`, or `503 { "status": "error", "message": string }`.

## `GET /api/files/*key`

<Badge text="GET" variant="info" size="medium" /> <Badge text="Any session" variant="default" size="medium" />

Serves a raw file straight from the storage backend — this is what backs
recipe hero photos and step photos. Not scoped to a recipe ID; `key` is
the full storage path, for example `recipes/<id>/image.jpg` or
`recipes/<id>/steps/<stepId>.jpg`.

**Response:** the file's bytes, with `Content-Type` inferred from the
path and `Cache-Control: public, max-age=31536000, immutable` (safe
since every photo is versioned by a `?v=` query param that changes on
update). `404` if the key doesn't exist in storage.

## `POST /api/mcp`

<Badge text="POST" variant="info" size="medium" /> <Badge text="No session required" variant="default" size="medium" />

The [MCP](/features/mcp) endpoint, using the Streamable HTTP transport in
stateless mode: every request is a standalone JSON-RPC message and the
reply is plain JSON. There are no sessions, and no streaming.

Send `Content-Type: application/json` and
`Accept: application/json, text/event-stream`. Tools act as the profile set
by `MCP_PROFILE_ID`, or the first admin when it isn't set — the
`recipery_profile` cookie is ignored here.

**Response:** a JSON-RPC response. A tool that fails (an unknown recipe, a
bad rating) still answers `200`, with `isError: true` in the tool result.
`403` for a request with an `Origin` header from another site, `405` for
`GET` and `DELETE`, and `403` for every request on the read-only demo.
